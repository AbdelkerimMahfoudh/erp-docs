| Store | Use |
| --- | --- |
| expo-secure-store | expo-secure-store (iOS Keychain / Android Keystore-encrypted SharedPreferences) through lib/storage.ts; on the WEB build the same wrapper writes plain window.localStorage (lib/storage.ts:10,20,32) |
| expo-file-system Paths.document | expo-file-system Paths.document (app Documents dir, plain JSON files) for offline queue, drafts, kept provider lists and the device catalogue cache |
| expo-file-system Paths.cache for CSV and PDF report exports and picked delivery files; expo-print, expo-image-picker and expo-document-picker also write their own files into the cache dir | expo-file-system Paths.cache for CSV and PDF report exports and picked delivery files; expo-print, expo-image-picker and expo-document-picker also write their own files into the cache dir |

Not used: AsyncStorage, MMKV, SQLite, IndexedDB, TanStack Query persistence: none found (grep of app/ components/ hooks/ lib/ constants/). The query cache is memory only.

What a sign-out or a completed deletion leaves on the phone (finding M-DEL-3, docs/85 §5):

- Sign-out leaves on the phone: the offline-queue file per user/company/branch (lib/offline/queue-store.ts:122-135 says clearScope is not called on sign-out, and nothing calls it at all), every draft file (lib/offline/drafts.ts:28), the sealed customer numbers of unsent money-service exchanges in SecureStore (lib/offline/exchange-numbers.ts:37), receipt and refund-receipt PDFs that expo-print writes to the cache (lib/receipt.ts:56, lib/refund-receipt.ts:142) carrying the customer's name and phone, picked delivery spreadsheets (lib/file-receiving.ts:56-100), DocumentPicker and ImagePicker cache copies (app/receive/pick.tsx:88 copyToCacheDirectory:true; app/expenses/new.tsx:168), auth.credentialNamespace (the sign-in phone number or personal ID, normalised: hooks/useAuth.tsx:38,194), the device credential (kept on purpose: hooks/useAuth.tsx:268-276) whose KEY NAME contains that identifier (lib/device-key.ts:140-142), and erp.lastStoreId (lib/device.ts:30,68).
- Account deletion clears only the device credential and auth.credentialNamespace (hooks/useAuth.tsx:253-259), then the Done button runs signOut (app/account/delete.tsx:254). Everything else in the line above stays, although the deletion copy says 'this phone forgets your login' (lib/i18n/en.ts:3637).
- iOS Keychain items survive an app uninstall; expo-secure-store is called with no options (lib/storage.ts:11,23,35), so the device credential, credentialNamespace, sealed customer numbers, lastStoreId, language and theme come back after a reinstall. The privacy policy should say so, or the app should clear the Keychain on the first launch after an install.
- Plain (not SecureStore) files hold business data: cart lines with cost (components/sell/types.ts:11ff), receive staging with costs and IMEIs, expense amounts and notes, return notes, loan notes, the counter exchange amount and commission. They rely only on the OS default file protection. Customer numbers and credentials are kept out of these files by key-name filters (lib/offline/draft-schema.ts:91-125, lib/offline/queue-schema.ts:43-78).
- Android backup: the expo-secure-store plugin sets android:fullBackupContent and dataExtractionRules to include only the sharedpref domain minus SecureStore (node_modules/expo-secure-store/android/src/main/res/xml/secure_store_backup_rules.xml), so Documents files and the cache are not backed up. On iOS the Documents directory (queue, drafts, catalogue, providers) IS in iCloud and device backups; nothing sets isExcludedFromBackup.

Clipboard: Personal ID (app/settings.tsx:632), Store ID (app/settings.tsx:689) and a partner code (app/(tabs)/partners.tsx:256) are copied to the system pasteboard on request (write only, never read).
